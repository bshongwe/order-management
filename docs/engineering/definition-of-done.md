# Definition of Done

A change is complete when the applicable criteria below are satisfied:

- [ ] Acceptance criteria are met and edge cases are considered.
- [ ] Business rules are enforced at the appropriate domain/application boundary.
- [ ] Code is readable, cohesive and avoids unnecessary abstraction.
- [ ] Automated tests cover meaningful behavior and regression risks.
- [ ] Validation and error responses are consistent with the API contract.
- [ ] No secrets, credentials or environment-specific values are committed.
- [ ] Logging and diagnostics are sufficient for operational troubleshooting.
- [ ] Documentation and examples are updated where behavior or setup changed.
- [ ] Formatting, build and relevant test checks pass.
- [ ] The pull request explains intent, implementation, testing and trade-offs.
- [ ] Changes are reviewed before merging; direct commits to `main` are avoided.

Not every checkbox applies to every documentation-only or mechanical change; explain exceptions in the pull request.
